# 番茄钟

一个极简的番茄钟：专注 25 分钟，休息 5 分钟。带**任务清单**、**今日统计**、**暗色模式**。

- **零依赖**：不装任何 npm 包，运行时不用框架
- **零构建依赖**：`node src/build.mjs` 是手写的 90 行脚本，只做字符串拼接
- **零第三方请求**：字体走系统栈，图标是内联 SVG，页面不连任何外部域名
- **纯静态**：产物是一堆普通文件，丢到任何静态托管都能跑
- **数据只在本地**：`localStorage`，无账号、无后端、不上传

唯一依赖是 **Node ≥ 18**，而且只在构建期用——产物本身不需要 Node。

---

## 快速开始

```bash
npm run build     # 生成 index.html + 番茄钟-单文件.html
npm run dev       # 起本地服务器 → http://localhost:5174
npm run preview   # 上面两步一起做

npm test          # 跑全部测试（真实 Chrome，106 项）
```

也可以完全不用 npm：

```bash
node src/build.mjs
node src/serve.mjs
```

> 构建产物 `index.html` 是自动生成的，**不要手改**——改了会在下次 `npm run build` 时被覆盖。
> 要改内容改 `src/index.mjs`。

### 两种打开方式

| 文件 | 说明 | 什么时候用 |
| --- | --- | --- |
| `index.html` | 外链 `assets/` 下的 CSS / JS | 正常部署（能缓存、好维护） |
| `番茄钟-单文件.html` | CSS / JS 全部内联，**零子资源请求** | 直接双击打开、发给别人、或 `assets/` 加载不出来时兜底 |

两个文件内容完全一致，只是打包方式不同。**如果你双击 `index.html` 发现没样式 / 按钮没反应，
先试 `番茄钟-单文件.html`** —— 它能排除掉"子资源加载失败"这一整类原因。

如果连单文件版都异常，页面会在 1.5 秒后显示一条红色警告条，说明脚本没跑起来
（正常情况下不显示）。看到那条警告基本就是浏览器拦截或控制台有报错，按 F12 看控制台即可。

## 功能

### 计时
- 专注 / 短休息 / 长休息三阶段，默认 25 / 5 / 15 分钟
- 每 4 个番茄进入一次长休息（可改）
- 进度环 + 倒计时数字跟着阶段变色（专注番茄红、休息墨绿）
- 阶段结束可选**播放提示音**（WebAudio 合成，不加载音频文件）与**桌面通知**

### 任务清单
- 输入框回车或点「添加」新增；勾选框标记完成；`×` 删除
- 显示「未完成 / 总数」
- 「清空已完成任务」（无已完成时自动禁用）
- 任务名最长 120 字，用 `textContent` 渲染，**不存在 XSS**

### 今日统计
- **今日番茄**：今天完成的番茄数
- **专注分钟**：今天累计专注时长
- **连续天数**：从今天（今天没记录则从昨天）往前连续有番茄的天数

「今天」按**本地自然日**算，不用 UTC——用 `toISOString()` 会在东八区把凌晨 0–8 点的番茄算到前一天。历史只留最近 **60 天**，防止 `localStorage` 无限膨胀。

### 暗色模式
- 设置里三选一：跟随系统 / 亮色 / 暗色
- 亮暗各一套令牌；暗色不是简单反相（暗底 `#141416` 而非纯黑，文字 `#ededf0` 而非纯白）
- 功能色在暗底上做了提亮（`#c0392b → #e8615a`），否则对比度只有 3.5:1，不过 AA
- 首帧前用内联脚本把主题写到 `<html>`，暗色用户不会看到一瞬白屏

### 快捷键
| 键 | 作用 |
| --- | --- |
| `空格` | 开始 / 暂停 |
| `R` | 重置 |
| `S` | 跳过当前阶段 |

焦点在输入框里时不拦截按键，不会影响正常打字。

## 数据

全部存在 `localStorage` 的 **`pomodoro:v2`** 一个键里：

```json
{
  "v": 2,
  "settings": { "focus": 25, "short": 5, "long": 15, "cycle": 4,
                "autoNext": false, "sound": true, "theme": "auto" },
  "history":  { "2026-10-17": { "done": 3, "seconds": 4500 } },
  "tasks":    [ { "id": "…", "text": "写番茄钟", "done": false, "createdAt": 0 } ],
  "cycleDone": 1
}
```

读取时逐项校验：类型不对或超范围的回落默认值，**但不整份丢弃**（其他项的有效设置应当保留）。
内容损坏时静默用默认值，不报错。

> 早期版本用过 `pomodoro:v1`（数据形状不同）。当前版本**不读取**旧键，也不删除它。
> 想清理可以手动执行 `localStorage.removeItem("pomodoro:v1")`。

## 部署

产物就是静态文件，把整个目录（去掉 `src/`、`.shots/` 也行）上传即可：

```
index.html
assets/pomodoro.css
assets/pomodoro.js
assets/main.js
```

没有路由、没有服务端要求，子目录部署也能用（**所有资源都是相对路径**）。

### 线上地址与发布方式

本站部署在 **GitHub Pages**：<https://zz26max.github.io/pomodoro/>
（仓库 `zz26max/pomodoro`，由 `main` 分支根目录发布，push 后自动构建）。

所以 **`index.html` 与 `番茄钟-单文件.html` 必须提交进仓库**：

- Pages 只发布仓库里真实存在的文件，不会替你跑 `npm run build`；
- 一旦把这两个文件写回 `.gitignore`，线上会退化成 GitHub 用 Jekyll 渲染的 `README.md`，
  番茄钟本身打不开——页面看起来"有内容"，但计时器根本没加载。

发布流程：`npm run build` → `git add -A && git commit` → `git push`，等 Pages 构建完成即可。
改了 `assets/` 或 `src/` 却忘了重新 build，线上会停在旧的产物上。

## 改默认时长要注意

两个地方必须一起改，否则会出现「无 JS 显示 25、有 JS 后变 30」：

| 位置 | 作用 |
| --- | --- |
| `src/index.mjs` → `POMO.defaults` | 无 JS 时的**静态兜底**展示值 |
| `assets/pomodoro.js` → `DEFAULTS` | **运行时真值**（会被 localStorage 覆盖） |

`assets/pomodoro.js` 的 `DEFAULTS` 是权威，`POMO.defaults` 是它的镜像。
同理 `LIMITS`（合法区间钳制）与 `field(...)` 里的 `min`/`max` 也要一致。

`npm run build` 会**自动检查这一项**，不一致会直接报出来。

## 测试

测试用真实的 headless Chrome 跑（CDP 直连，零依赖，不用 puppeteer）。

```bash
npm test                  # 134 项，全绿
npm run test:functional   # 48 项：计时 / 阶段 / 任务 / 持久化 / 主题 / XSS / 快捷键
npm run test:flow         # 20 项：设置钳制 / 进度点 / 统计结算 / 亮暗对比度
npm run test:ui           # 20 项：环的几何 / 真实点击 / 空输入反馈 / 按钮可点性
npm run test:narrow       # 28 项：240–768px 七档视口（侧边栏）无溢出 + 可点击
npm run test:boot         #  9 项：启动自检报警 / 脚本缺失时不刷新
npm run test:single       #  9 项：单文件版在 file:// 下可用
npm run shoot             # 生成截图到 .shots/（人工看版面）
```

`test-flow.mjs` 里有一步会**真实等 62 秒**走完一个专注阶段，验证统计确实会记账。
不想等可以设 `SKIP_SLOW=1` 跳过。

### 写测试时踩过的坑

1. **不能用 `file://` 测**。Chrome 在 `file://` 下禁用 `localStorage`，会抛 `SecurityError`，
   任务 / 统计 / 主题全部误判为坏掉。必须起 http 服务器。
2. **改完 `data-theme` 不能立刻读 computed 颜色**。在同一个同步块里
   「改属性 + 读 `getComputedStyle`」，部分元素的 `color` 仍返回旧值
   （变量更新了，`color` 没重算），会误报一片「对比度不达标」。
   要拆成两次往返、中间等约 400ms。
3. **`<details>` 折叠时内部元素是 `display:none`**，样式根本不重算，
   测它们之前必须先 `open = true`。
4. **模拟点击前必须先 `scrollIntoView`**。元素在页面下方时
   `getBoundingClientRect()` 返回的坐标超出视口，CDP 的鼠标事件会打在空白处——
   看起来是「点击无效」，其实是**根本没点中**。这个坑在写 `test-ui.mjs` 时踩过，
   一度把「测试没有点中按钮」误判成「按钮坏了」。

### 「行为通过」不等于「体验正确」

最初的 68 项测试全绿，但用户一上手就发现两个明显问题。原因是测试只覆盖了行为：

| 用户反馈 | 为什么原测试没抓到 |
| --- | --- |
| 点「添加」没反应 | 测试用 `form.dispatchEvent("submit")` 模拟，**绕过了真实点击路径**；也从未断言「空输入时有没有反馈」 |
| 计时环被裁成方形 | 只断言「环有尺寸」，**没断言宽高相等**，也没断言「没超出画布」 |

所以 `test-ui.mjs` 刻意改成用**真实鼠标事件**（CDP Input 域），并且把几何量出来断言。
凡是「看起来对不对」的东西——几何、可点性、空态反馈——都必须单独写断言，
不能指望功能测试顺带覆盖。

### 「跑在我机器上」不等于「跑在用户机器上」

即使 88 项测试全绿，用户仍然反馈「添加没反应」。继续排查后发现，
**所有测试都跑在 http:// 下，而用户很可能是双击 `index.html`（`file://`）打开**。
这类环境差异测试不容易覆盖到，所以补了两层兜底：

1. **`onsubmit="return false"`** —— 万一脚本没跑起来，点「添加」也不会触发原生表单提交
   把页面刷掉（否则表现为"没反应，而且刚打的字也没了"）。
2. **启动自检** —— 1.5 秒内脚本没跑到最后，页面直接显示红色报警条说明原因，
   而不是让用户对着一个"点不动的按钮"猜。
3. **单文件版** —— `番茄钟-单文件.html` 把 CSS/JS 内联，排除"子资源加载失败"整类原因。

`test-boot.mjs` 与 `test-single.mjs` 就是为这两层兜底写的回归测试
（含"故意让 pomodoro.js 404"的故障注入）。

### 「宽屏正常」不等于「窄屏正常」

用户最后补充的关键信息是：**浏览器里正常，侧边栏打开就出问题**。
侧边栏的本质是**视口很窄**（约 240–420px），而此前所有测试都跑在 1100px 宽。

一测就复现了：280px 下页面横向溢出 39px，`240px` 下溢出 79px，
「添加」按钮被推到视口右边界之外（`clipped: true`），点击自然落空。

根因不是任务区，而是外层容器的这样一行：

```css
.pomo { display: grid; place-items: start center; }   /* ← 有问题的写法 */
```

`center` 会让栅格轨道按 **max-content** 定宽（实测 319px）。
宽屏下 max-content 小于视口，看不出问题；一旦视口窄到 300px 上下，
轨道仍然坚持 319px，整页被撑宽，右侧内容全被推出屏幕。

**修法**：给轨道显式可压缩的上限。

```css
.pomo {
  grid-template-columns: minmax(0, 1fr);  /* 轨道永不超过容器宽度 */
  align-items: start;
  justify-items: center;
}
```

`test-narrow.mjs` 把 240 / 280 / 320 / 360 / 375 / 420 / 768 七档视口全部锁死：
无横向溢出、按钮未被裁切、环是正圆、点击能加任务。

> 教训：**"响应式"不能只靠 600px 断点验证**。要在最窄的真实容器里量
> `scrollWidth - clientWidth`，而不是只看元素"有没有尺寸"。

## 修过的两个体验问题（2026-10）

### 1. 计时环被裁成方形

**现象**：环的上下左右四条边是平的，整体像方形而不是圆。

**原因**：`viewBox="0 0 100 100"` + `r=52` + `stroke-width=4`。
描边外沿到圆心 = `52 + 4/2 = 54`，但 viewBox 中心到边界只有 `50`，**超出 4 个单位**。
SVG 默认 `overflow: hidden`，超出的部分被直接切掉。
实测外围 291px、容器 280px，多出来的 11px 就是被裁剪的证据。

**修法**：viewBox 放大到 `116`，圆心移到 `58,58`，留出 4 个单位余量
（`54 ≤ 58`）。同时给 `.pomo__ring` 加 `overflow: visible` 作双保险。
`pomodoro.js` 的 `RADIUS` 与模板的 `RING_R` 必须一致——周长按它实算。

### 2. 点「添加」没反应

**三个独立原因叠在一起**：

1. **空输入点按钮完全静默** —— 没有新任务、没有提示、焦点也不动。
   空输入下用户唯一能得出的结论就是「坏了」。
2. **按钮看着不像能点** —— 只有 `--line`（#e4e4e7）那种极浅的 1px 边框，
   在白色输入框旁边几乎不可见，读起来像一块静态灰块。
3. **回车不能提交** —— 只依赖表单的隐式提交，某些场景下不触发；
   而且中文输入法里回车是「确认候选词」，需要区别对待。

**修法**：
- 空输入时：聚焦输入框 + 输入框抖一下 + 显示一行提示「先在上面写一件事，再点「添加」。」
  （减少动效时关掉抖动，但**保留文字提示**——那是唯一的反馈渠道）
- 按钮改成深色实心（`--ink` 底 + 反白字），与页面底色对比度 17.7:1，一眼可点
- 显式处理回车；用 `compositionstart/end` + `e.isComposing` 排除输入法确认词
- 新增后自动滚到新任务，避免「加了但看不见」

## 浏览器支持

现代浏览器（Chrome / Edge / Firefox / Safari 近几年版本）。用到的特性：

`CSS 自定义属性`、`prefers-color-scheme`、`IntersectionObserver`、
`requestAnimationFrame`、`localStorage`、`Web Audio`、`Notification`、
`<details>`、`aspect-ratio`、`translate`/`scale` 独立属性。

所有可选能力都做了特性检测，缺失时优雅降级：

- 没有 `Notification` → 隐藏通知按钮，计时照常
- 没有 `AudioContext` → 静默不响，计时照常
- 没有 `IntersectionObserver` → 内容直接全部显示
- `localStorage` 被禁用（隐私模式）→ 计时照常，只是不记忆

## 设计说明

- **彩色只出现在细环、倒计时数字、1px 状态线、进度点上**，绝不铺大面积底色。
  整个页面的彩色面积占比极低，这是克制感的来源。
- **圆角接近 0**（`--r: 2px`），锐利感来自这里。
- **无 JS 时页面完全可读**：入场动效的初始态全部挂在 `.js` 类下，
  没有 JS 就是终态；`<noscript>` 里给出明确说明，而不是留一个点了没反应的按钮。
- **计时不用 `setInterval` 累减**：后台标签页里定时器会被节流，
  累减必然走慢。这里记录目标时间戳，只让 rAF 负责刷新显示，
  切回前台读一次 `Date.now()` 就自动追平，不累计误差。

想整体换调性，只改 `assets/pomodoro.css` 顶部的 **00 设计令牌**那一段。
